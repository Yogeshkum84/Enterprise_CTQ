YK ENTERPRISE

Dynamic CTQ Framework Specification

Document ID: YK-SPEC-2025-001
Version: 1.0.0
Status: PROPOSED

1. Executive Summary

Currently, the CTQ engine applies a Global Scoring Model (42 criteria applied to all tickets). The goal of this enhancement is to transition to a Contextual Scoring Model. The system must allow Administrators to define specific "CTQ Sets" based on the Ticket Type (Incident, Service Request, Chat, Call), ensuring that only relevant criteria are audited and weighted.

2. Logical Architecture

The system will move from a 1:1 relationship (Ticket $\rightarrow$ Global CTQ) to a 1:M relationship (Ticket Type $\rightarrow$ CTQ Set).

Step 1: Identify Ticket Type (e.g., "Incident")
Step 2: Fetch associated CTQ Set ID (e.g., "SET_INC_01")
Step 3: Load only the criteria linked to that Set ID
Step 4: Apply Set-specific weights (Sum must = 100%)
Step 5: Compute Overall Score based on the filtered subset

3. Data Schema Design

To achieve this, we need to separate the Definition of a CTQ from its Assignment to a set.

3.1 Master CTQ Table (The Library)

Field Type Description
ctq_id String (PK) Unique identifier (e.g., CTQ_01)
criteria_name String The name of the audit question
pillar String The quality pillar it belongs to
scoring_logic JSON/Regex The rule used to score the ticket

3.2 CTQ Set Table (The Templates)

Field Type Description
set_id String (PK) Unique ID for the set (e.g., SET_INC)
set_name String Human-readable name (e.g., "Incident Audit Framework")
ticket_type String The type this set targets (Incident, SR, etc.)

3.3 Set Mapping Table (The Weights)

Field Type Description
set_id String (FK) Link to the CTQ Set
ctq_id String (FK) Link to the Master CTQ
weight Float The specific weight for this set

4. Admin UI Workflow

The Admin Panel will be enhanced with a Framework Manager.

  • Create Set: Admin creates a new set (e.g., "Chat Audit") and assigns it to the "Chat" ticket type.
  • Pick & Choose: Admin sees a list of all 42 Master CTQs with checkboxes. They select only the 15-20 that apply to Chats.
  • Dynamic Weighting: Once selected, a weight input appears for each. The UI provides a Real-time Total; the "Save" button remains disabled until the total equals exactly 100%.
  • Quick-Clone: Ability to copy the "Incident Set" and create a "High-Priority Incident Set" by simply adjusting a few weights.

5. Scoring Engine Impact

The scoring function in server.py will be updated as follows:

PYTHON PSEUDOCODE

def score_ticket(ticket):
    t_type = ticket.type # e.g., "Service Request"
    ctq_set = db.get_set_by_type(t_type)
    criteria_list = db.get_criteria_for_set(ctq_set.id)

    total_weighted_score = 0
    for item in criteria_list:
        score = execute_logic(item.logic, ticket.content)
        total_weighted_score += (score * item.weight)

    return total_weighted_score

6. Summary of Benefits

Metric Global Model (v2.0) Dynamic Model (v3.0)
Accuracy Low (Scores irrelevant criteria) High (Context-aware scoring)
Admin Effort Single point of failure Modular and scalable
Agent Fairness Agent penalized for missing "SLA" in a Chat Agent only scored on "Chat-relevant" CTQs
